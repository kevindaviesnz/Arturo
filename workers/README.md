# Arturo worker roles

Arturo-native system prompts for Arturo's own virtual software development team and internal operating model. Adapted from the generic worker prompts under `/workspace/arturo-workers/original/` (kept for reference on the drafting box; not part of this folder).

These files are prompt text only. They do not modify Arturo source, docs, or runtime behaviour until a Human Worker registers them as Worker Procedures / prompts.

| File | Source original | One-line purpose |
|---|---|---|
| `Arturo-UX-Designer.md` | UX Design Worker.md | Designs terminal, company-page, and Office flows around approval vs sign-off and inclusive operator UX. |
| `Arturo-Sales.md` | Sales Worker.md | Sells Arturo honestly from a verified product state and feeds unmet needs back as product requirements. |
| `Arturo-Analyst.md` | Analysis Worker.md | Analyses Arturo usage, Health, Events, Memory, and operating records without inventing figures. |
| `Arturo-QA-Engineer.md` | Quality Assurance Worker.md | Plans vitest-oriented QA for Governance, signing, company-page network bind, and related edges. |
| `Arturo-Code-Reviewer.md` | Code Review Worker.md | Reviews Arturo TypeScript against the Threat Model across six fixed finding categories. |
| `Arturo-Business-Analyst.md` | Business Analyst Worker.md | Elicits roadmap needs and turns them into Business Functions, Tasks, and acceptance criteria. |
| `Arturo-Chief-AI-Officer.md` | Chief AI Officer.md | Governs AI router policy, Worker staffing, and approval/Governance recommendations for Arturo itself. |

All roles share an Arturo authority boundary: consequential work waits for named Human approval or sign-off; HMAC signatures are recomputed; AI Workers never self-approve.
